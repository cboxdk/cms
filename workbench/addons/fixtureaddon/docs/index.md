# Fixture addon

The documentation of the workbench's fixture addon, cboxdk/cms-fixture-addon, in the namespace fixtureaddon. It extends the workbench's type app:fixture_article with the field ext.fixtureaddon.fixture_slug, derives the slug from the title on entry.create and entry.revise, requires a slug set by hand on entry.create to be well formed (RequireWellFormedSlug), requires the slug when a revision of the type is released (variant.release), and refuses a grant to oneself on grant.assign (DenySelfGrant, its four-eyes rule). The kernel never requires an extension field itself: the owner's code creates and revises entries without knowing it, so only a validate hook at a release asks for it. It owns the query fixtureaddon.articles, the articles of the type with their slugs, exposed on REST and in the panel, whose result classifies an article's title internal, and the command fixtureaddon.slug.set, which sets the slug of an article in a new revision of its shared variant, with its own value class ArticleSlug, a well-formed slug, exposed on REST and in the panel.

In the panel it contributes to every kind of contribution and every point of block B1, so the panel's extension model is exercised end to end by the workbench's browser tests. On the generic command form of entry.create: the checks fixtureaddon.slug-hint (a warning where the title derives no slug), fixtureaddon.slug-override (an acknowledgement of a slug set by hand) and fixtureaddon.slug-shape (an error for a slug that is not well formed, which mirrors RequireWellFormedSlug, so it may block the submit), the step fixtureaddon.slug-review before the submit, which shows the slug the article gets and patches it into the draft or stops the run, the aside fixtureaddon.slug-help, the decorators fixtureaddon.submit-note and fixtureaddon.receipt-note, and fixtureaddon.dry-run-note below what a dry run would change. On the form of its own command fixtureaddon.slug.set: the replacement fixtureaddon.slug-input of the input of the member bound to ArticleSlug, the one value class the addon owns, which shapes what is typed into a slug. On the form of grant.assign: the check fixtureaddon.self-grant, which blocks a grant to the viewer themselves and mirrors DenySelfGrant, and the step fixtureaddon.four-eyes, which asks the viewer to confirm that a second person reviewed the grant. In the shell: the page fixtureaddon.articles at /x/fixtureaddon/articles with its nav entry fixtureaddon.articles-link, both for a viewer who holds fixtureaddon.articles, the action fixtureaddon.new-article of the viewer's menu, which opens the form of entry.create, and the observer fixtureaddon.activity, which records the last command that completed in the browser's session storage. On the who-am-I page: fixtureaddon.recent-activity, fixtureaddon.my-articles and fixtureaddon.faulty, which throws when it renders so that the panel's isolation of a failing contribution can be seen; the workbench disables it through the kill switch, cbox-cms.panel.disabled. On the grants and roles pages the notes fixtureaddon.four-eyes-note and fixtureaddon.articles-permission, and on the login page the notice fixtureaddon.login-notice, data alone. The addon reads public fields, so the panel hands its page and sections the query's result without the titles, whatever the viewer may read.

Their code is the panel bundle in dist/panel, built from resources/panel and signed with the test key panel-signing-test-key.pem; the workbench trusts that key's public key in cbox-cms.addons.publishers, so cms:build verifies the signature as it does for any addon. resources/panel/parity/slug-shape.json holds the mirrored slug check and its hook to the same verdicts, and resources/panel/parity/self-grant.json the self-grant check and DenySelfGrant.
