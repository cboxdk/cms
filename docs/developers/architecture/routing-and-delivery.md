# Routing and delivery

`path.resolve` maps a host, locale and path to a placement and decides its visibility; `GET /v1/resolve` serves the answer as a fragment.

## path.resolve

`path.resolve` (PRD 5.8, 5.9, 6.6, GUARDRAILS 5) is the query action `Cbox\Cms\Core\Routing\Actions\ResolvePathAction`, registered on no surface, of the query `Routing\Domain\Queries\ResolvePath` (a `Host`, a `Locale` and a `RequestPath`). It maps the host to a site through `Routing\Domain\SiteHosts`, the configured sites of `cbox-cms.sites` (handle to `origin` and other `hosts`, read by `Routing\Boundary\SitesConfig`; never the request's host for a URL), finds the longest route of the site in the locale among the path's prefixes in `node_routes`, looks the rest up as one slug in (node, locale, slug) of the placements' released stage, below the source for a mount, which is shown identical to the source and never canonical, refuses a type whose blueprint says `routable: false`, and decides `Routing\Domain\VisibilityPrecedence` at the Clock's time over the rungs M1 reaches (entry lifecycle, variant withdrawn, placement withdrawn, released revision for a type with stages, the window), from the window and not the stored state. The answer, `Routing\Domain\Dto\ResolvedPath` (`ReadsContent`), holds the entry whenever its placement and entry were read, so the answer carries `e-` and `n-` keys also when it is not visible, with the fields of its released row in its type's table (`RouteReader::released()`) only when the placement is visible, and a `PathExplanation` with a `ResolveOutcome` and each step reached (site, route, node, mount, placement, visibility with `validUntil`, canonical URL from the canonical placement's site origin). Its reads are the port `Routing\Domain\RouteReader`, bound to `Routing\Adapter\PostgresRouteReader`: four statements at most (`ResolvePathAction::COST`), under the read's actor context, so the count does not grow with the placements below a node (`packages/core/tests/Postgres/PathResolutionTest.php`); the fake is `FakeRouteReader`, held to it by `RouteReaderBehaviour`. Every context reads `node_routes` (`node_routes_read`), and the kind, mount source and tree root of a node that has a route through the SECURITY DEFINER function `cms_routed_node`; the nodes' own policies are unchanged. The anonymous context reads only placements stored `live`, so a scheduled placement whose window has opened resolves for the public once the scheduler (B3) moves it.

## The delivery API

The delivery API (PRD 8.9, 8.10, 8.12, MILESTONES M1 point 5) is `GET /v1/resolve?site=<host>&locale=<locale>&path=<path>`, registered by `Cbox\Cms\Http\Delivery\DeliveryRoutes::register()` outside the web group (the workbench does it in `workbench/routes/api.php`), served by the logic-free `Http\Delivery\ResolveController` with the Boundary `DeliveryInput` (only the known parameters; the Bearer credential only with `debug=1`) and `DeliveryOutput` (status, `application/json` or `application/problem+json`, `Surrogate-Key` with the content keys, `Cache-Control` `public, max-age=0, s-maxage=N` with `stale-while-revalidate` and `stale-if-error` only for a 200 whose window never ends, or `private, no-store`, and `Cbox-Cache: hit|miss`; no cookie, no `Vary`). The action `Cbox\Cms\Core\Delivery\Actions\DeliverPath` checks the parameters (`validation_failed`), refuses a host no site in `cbox-cms.sites` is served at with `host_not_configured` (421) before any fragment or read, serves the fragment of (host, locale, path) (`DeliverPath::fragmentKey()`) from the `FragmentStore` when there is one, without the query pipeline, and otherwise runs `path.resolve` through its own `QueryPipeline` (a contextual binding in `CoreServiceProvider` with `Delivery\Domain\DeliveryAuthorizer`, which allows `path.resolve` for anyone and nothing else) as the anonymous principal. `Delivery\Domain\PathAnswers` maps the result: resolved is 200 with the record, withdrawn or tombstoned or purged is `path_gone` (410), everything else `path_not_found` (404); the keys are the read's plus `n-` of the node the slug was looked up under; the lifetime is the lower of `cbox-cms.delivery.max_age_seconds` and the window's next change (`VisibilityStep::validUntil`). The record is the generated record DTO through the contract `Cbox\Cms\Contracts\Codecs\RecordCodecs` at the public classification access (invariant 10): `cms:generate` writes `GeneratedRecordCodecs` (bound by the generated provider), which hands the entry and its codec to the core's `Codecs\Boundary\RecordDocument`; the testkit has `FakeRecordCodecs` and the shared suite `RecordCodecsContract`. The answer is stored as a `Fragment` built at the read's position; a `FragmentFenced` answer is sent with `no-store` (PRD 8.12 point 1). With `debug=1` the read runs as the credential's principal and the body holds the `PathExplanation`, only for an actor whose classification access is at least internal (else `unauthorized`), never stored or shared. The documents are the port `Delivery\Domain\DeliveryDocuments`, bound to `Delivery\Adapter\JsonDeliveryDocuments`, with `FakeDeliveryDocuments` held to it by `DeliveryDocumentsBehaviour`; it writes every document through a generated codec: `delivery.v1.json` (`Delivery\Domain\Dto\DeliveryDocument` with `DeliveryMeta`), `delivery-explanation.v1.json` (`DeliveryExplanation`), `problem.v1.json` and, for the fragment, the core's `delivery-fragment.v1.json` (`StoredAnswer`), with the record, the explanation and the problem embedded as `Contracts\Codecs\JsonDocument`s (`docs/addons/delivery-json.md`). `packages/http/tests/Postgres/DeliveryResolveTest.php` runs it over HTTP on Postgres and Valkey; `docs/developers/delivery.md` describes it.
