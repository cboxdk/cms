# The event log and the runner

Every commit appends its events to the log, and the runner hands them to subscribers below the transaction horizon, one lane per process.

## The event log

The event log (PRD 7.2 to 7.5, 7.10, GUARDRAILS 2.4) has its contract in `Cbox\Cms\Contracts\Events`. An event is a class that implements `Event`: the static `type()` gives its `EventType` (a name in the form of `EventType::NAME_PATTERN`, such as `variant.released`, and the payload version from 1), `aggregate()` its `EventAggregate` (an `AggregateType`, the id and the aggregate version from 1) and `payload()` a final readonly DTO that implements `EventPayload`, whose `data()` gives the same values as `EventData` of named `EventDatum`s. There is no datum for a string: a datum is an id (`EventDatum::identifier()` of an `Cbox\Cms\Contracts\Ids\Identifier`, whose `toString()` must match `EventIdentifier::PATTERN`, visible ASCII without spaces), a `TextHash` (SHA-256 of a text), an int, a bool, a UTC `DateTimeImmutable`, a backed enum's value (a word, `EventDatum::ENUM_PATTERN`), null or a list; anything else throws `InvalidEvent`, whose messages never repeat a refused string (PRD 6.5 invariant 10). `ChangesetId` implements `Identifier`. The testkit's PHPStan rule `EventPayloadTextRule` reports `cboxCms.eventPayloadText`, non-ignorable and in test code too, for a property of an `EventPayload` whose type can hold a string (string, a string in a union, `list<string>`, mixed) unless it is an `Identifier` or a `TextHash`, and for any type an event cannot carry (float, an array that is no list, `DateTimeInterface`, an object that is no `Identifier`, `TextHash`, `DateTimeImmutable` or backed enum); its fixture is `packages/testkit/tests/Phpstan/Fixtures/EventPayloads.php.inc`. The core migration `*_create_events_tables.php` makes `events` (LIST on `stream`, `interactive` or `bulk` as `EventStream`, then RANGE on `event_id` from the sequence `events_event_id_seq`, owned by `event_id`; primary key `(stream, event_id)`; `xid` defaults to `pg_current_xact_id()` and `generation`, the failover generation, to the WAL insertion timeline read from `pg_walfile_name(pg_current_wal_lsn())`; `type` and `type_version`; `data` jsonb in `Events\Boundary\EventDataJson`'s form, an object of one-member objects named by `DatumKind`; indexes `events_position (xid, event_id)` and `events_occurred_at`; the app role has SELECT and INSERT), `event_cursors` (a cursor per subscription and stream as `(xid, event_id)`; the app role may UPDATE only `xid`, `event_id` and `updated_at`) and `event_parked_aggregates` (one row per subscription and aggregate). `events_interactive` and `events_bulk` are listed in `cbox-cms.database.partitions.tables` with key `bigint`, width 1000000, the shared sequence and 30 days' retention on `occurred_at`. `Cbox\Cms\Core\Events\Infrastructure\EventWriter::write(ChangesetId, EventStream, list<Event>)` inserts on the caller's connection inside the caller's transaction, throws `TransactionRequired::forEvents()` before any statement without one (`transactionLevel()` below 1), never begins one, takes `occurred_at` from the Clock, inserts up to `EventWriter::CHUNK` events per statement and returns their `EventPosition`s in the order given; a row no partition covers throws `PartitionMissing` through `Partitions\Boundary\MissingPartition`, which Infrastructure may use where `Adapter\MissingPartitionMapper` delegates to it. `EventReader::after(EventStream, EventPosition, int $limit)` (1 to `MAX_LIMIT`) returns `StoredEvent`s of the stream after the cursor below the horizon, `xid < pg_snapshot_xmin(pg_current_snapshot())`, in `(xid, event_id)` order, on the write PDO; `EventPosition::start()` is before every event. Row mapping is `Events\Boundary\EventRows`. `packages/core/tests/Postgres/EventLogTest.php` covers the writer and reader with independent connections and waits up to 30 s for the horizon, which another checkout's open transaction can hold back; the page is `docs/addons/events.md` with the example `examples/Postgres/Events/RecordStockCountedTest.php`.

## The event runner

The event runner (PRD 7.4 to 7.8, `docs/addons/subscribers.md`) is `cms:events:run [--lane=critical] [--until-idle]`, the cli's `Console\RunEventsCommand`, which calls the action `Cbox\Cms\Core\Subscriptions\Actions\RunLane::run(LaneRun, RunnerStop)`; one process per lane, and only the critical lane is built (`Cli\Boundary\SubscriptionArguments::lane()` refuses the others with exit 64). It runs the subscribers as the service actor `cbox-cms.events.runner.service_actor` names (PRD 6.5 invariant 21), read through the `ActorDirectory` before each round: none, an unknown actor or one not of class service throws `ServiceIdentityRefused` with `subscription_identity_invalid` (exit 78), one that is not active with `actor_not_active` (exit 77). An addon's subscription runs instead as the addon's service actor, which `Core\Addons\Actions\ResolveSubscriberActor` gives each round; one whose actor is unavailable is refused for the round (`addon_service_actor_unavailable`, `LaneReport::$refused` of `Domain\Dto\RefusedSubscription`, printed and logged by the command) and keeps its cursor, while the others run. Each subscription's batches run under its actor's `AccessContext`, compiled once per actor and round by `AccessContexts` for a service principal, which `SubscriptionLog::transaction(SubscriptionName, AccessContext, Closure)` sets with `ActorContext::set()` right after READ COMMITTED, so row level security bounds what the subscriber reads and writes on the connection. `Subscriber::handle(StoredEvent, Delivery)` gets a `Contracts\Subscribers\Delivery` with the subscription's actor, the try from 1 and `release`. The runner's ports are `Subscriptions\Domain\SubscriptionLog` (`Adapter\PostgresSubscriptionLog` on the default connection), `LaneSubscribers` (`Adapter\RegistryLaneSubscribers`, the compiled registry and the container) and `Pacing` (`Adapter\SystemPacing`, `hrtime()` and `usleep()`), with fakes in `packages/core/tests/Subscriptions/Fakes` held to them by `SubscriptionLogBehaviour`, `LaneSubscribersBehaviour` and `PacingBehaviour`; the settings are `RunnerSettings` from `cbox-cms.events.runner` (`Boundary\RunnerConfig`). A round gives each subscription of the lane one batch of its released aggregates and one batch per stream. A batch is `SubscriptionLog::transaction()`: one transaction at READ COMMITTED that takes `pg_try_advisory_xact_lock(SubscriptionLock::of($name))` and gives null without running when another runner holds it, and never nests (`SubscriptionTransactionOpen`). In it the runner reads at most `batch_size` events after the cursor below the horizon through the `EventReader`, passes those of types the subscription does not receive and those whose aggregate is parked for it, parks an aggregate whose event failed `max_attempts` tries in a row, hands the others to the subscriber, stops handing after `batch_budget_ms` (at most 1900), moves the cursor with an upsert that never moves back, and commits, so the cursor commits with what the subscriber wrote on the connection. A subscriber that throws rolls the batch back (`SubscriberFailed`); the units before it are handed again at once in a batch that ends before it, and it is tried again after `backoff_base_ms` doubled per failed try up to `backoff_max_ms`; the failed tries are counted per run in `Domain\LaneState`. `cms:events:release <subscription> <type>:<id>` (`ReleaseParked`, `subscription_unknown` or `subscription_not_parked`, exit 65) sets `released_at`; the next release batch hands the newest event of the aggregate at or before the subscription's cursor in each stream (`SubscriptionLog::newest()`, the index `events_aggregate`) once with `release` true and deletes the row, or after `max_attempts` failed tries clears `released_at` and adds the tries; an aggregate with no such event left is unparked and reported. `cms:events:parked [subscription]` (`ListParked`) lists the parkings. The migration `*_add_release_to_event_parked_aggregates.php` adds `released_at` and `events_aggregate`. `packages/core/tests/Postgres/EventRunnerTest.php` shows that no event is skipped when transactions commit out of event_id order, that a failing subscriber parks one aggregate after its tries while the others flow and its current version is handled once after release, and that an addon's subscriber sees `cbox_cms.actor` equal to the addon's service actor and a kernel subscriber the runner's; `packages/cli/tests/Postgres/EventsCommandsTest.php` covers the commands.
