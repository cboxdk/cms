# The JSON contracts

Every document a surface sends or receives has a JSON Schema and a generated codec on both sides; nothing serialises a contract by hand.

## The kernel's JSON contracts

The kernel's JSON contracts (GUARDRAILS 2.2, PRD 6.1, 8.4, 8.8) are JSON Schemas of draft 2020-12 in `packages/contracts/resources/schemas`, one file per contract version: `receipt.v1.json` (the `Receipt`: `changeset_id`, `consistency_token`, `outcome`, `position`, `projections`, `retention_class` and `wait_level`, every key present), `problem.v1.json` (RFC 9457 problem details, `Errors\Problem`: `type`, `title`, `status`, `detail`, `instance`, the catalog `code`, `retryable` and `errors`, each a `Results\CatalogError` written as `code`, `detail` and `field`) and `envelope.v1.json` (the envelope fields a caller sends, `Envelope\RequestEnvelope`: `idempotency_key` required, and `correlation_id`, `wait_level`, `dry_run`, `on_behalf_of` and `provenance` with their defaults), and the delivery and explanation documents `delivery.v1.json`, `delivery-explanation.v1.json`, `path-explanation.v1.json` and `explained-path.v1.json`, with the core's own `packages/core/resources/schemas/delivery-fragment.v1.json` (`ProtocolSchemas::CORE_SCHEMA_DIRECTORY`). `composer generate:protocol` (`tools/bin/generate-protocol.php`, `Cbox\Cms\Tooling\Protocol\Adapter\ProtocolGeneration`) reads each through the generators' `Protocol\Boundary\JsonSchemaContract` into a `CodecContract` bound to the classes of the contracts by `Protocol\Domain\ProtocolSchemas::kernel()` (a `SchemaBinding` per file: a class per object by the JSON pointer of its definition, a `ValueBinding` per id, value object or enum by the pointer of its place, and property names that are not the key in camelCase), and writes `EnvelopeCodecV1`, `ProblemCodecV1`, `ReceiptCodecV1`, `DeliveryCodecV1`, `DeliveryExplanationCodecV1`, `PathExplanationCodecV1`, `ExplainedPathCodecV1` and `DeliveryFragmentCodecV1` (`#[Experimental]`) with `PhpCodecEmitter` into `packages/core/src/Codecs/Boundary/Generated`, which it owns; no DTO is generated for them. The reader takes only the keywords the codec has a form for and refuses every other with `generate_schema_invalid` (exit 65; a missing schema is `generate_schema_missing`, 66): an object has `additionalProperties: false`, a key that is not required has a `default` the codec gives it when it is missing, a nullable value is `type` of a type and `null` or `anyOf` of a `$ref` and `null`, a string with a `pattern` must be bound to a class whose constructor checks it, and an enum's values must be the PHP enum's in order. Reflection at build time holds each bound class to its object: a constructor argument per key, by name, of the key's type, nullability and default, and a public property to write it from. For these codecs the codec model has three more pieces: a `CodecObject` bound to a class (`$class`, built with `new` and its named arguments in the constructor's order through `JsonValues::build()`, which turns the class's `InvalidArgumentException` into `json_invalid` at the object), a `CodecProperty` that is `nullable` (the key is required and may be null, `JsonValues::present()`) or has a `default` (`JsonValues::defaulted()` and `defaultedNullable()`), and `CodecKind::Value`, a value object of one string made with `new` and written from its `value` (`JsonValues::value()`). A committed `Receipt` carries its commit `position`, a `Consistency\CommitPosition` written as a decimal string, and may carry its `consistencyToken` (JSON `consistency_token`), a `Consistency\ConsistencyToken` (the Postgres timeline as `generation`, 1 to 4294967295, and a `Consistency\LogSequenceNumber` as Postgres writes a `pg_lsn`); a receipt that committed nothing has neither. `Problem::of()` builds a problem from a code's catalog entry, and its constructor refuses a type, status or retryable that is not the catalog's. `FieldPath::fromString()` reads the form `toString()` writes. `composer check:generated` regenerates the codecs, and `tests/Arch/GeneratedCodecsTest.php` (`tests/Support/Arch/HandWrittenCodecScan.php`) fails on code in `packages/*/src` or `workbench/app` outside a `Generated` directory that names a bound class and writes or reads JSON, directly or through a JSON helper (a class outside a `Generated` directory that writes or reads JSON and takes or gives a `stdClass` in a public method, named by import or in the file's own namespace), on a class there that implements `JsonCodec`, and on a bound class that serialises itself. A member that is a document of another contract, such as the record of a delivery answer, is `CodecKind::Document` (`ValueBinding::document()`, a `JsonDocument` embedded as its own codec wrote it, `JsonValues::document()` and `encodeDocument()`, TypeScript `JsonObject` with the rule `document`). `packages/core/tests/Codecs` round-trips each through its codec and validates the output against its schema with opis/json-schema. The pages are `docs/addons/receipt-json.md`, `problem-details.md`, `envelope-json.md` and `delivery-json.md`.

## The TypeScript of the contracts

The TypeScript of the contracts (PRD 11.12, GUARDRAILS 2.2 and 9) is written by cms:generate's `Generation\Domain\Generators\TypeScriptContracts` into the TypeScript directory (`workbench/resources/js/cms/generated`), next to `TypeScriptTypeHandles`' `index.ts`: `validation.ts`, the runtime, copied byte for byte from `packages/generators/resources/typescript/validation.ts` (read by `Generation\Boundary\TypeScriptRuntime`); `records/<Owner><Handle>V1.ts` per type from `RecordContracts`; and `protocol/EnvelopeV1.ts`, `ProblemV1.ts`, `ReceiptV1.ts` and one module per kernel command, such as `CreateEntryV1.ts`, from the kernel's schemas (read by `Protocol\Boundary\KernelContracts`, the same `CodecContract`s `composer generate:protocol` emits). `Codec\Domain\TypeScriptEmitter` writes each module from a `CodecContract`: an interface per object with the JSON keys (snake_case, extension fields under `ext.<namespace>.<handle>`, rich text as the runtime's `PortableText`), a union type per select (`<Object><Property>Choice`) and per bound enum (its short name), `key: T`, `key: T | null`, `key?: T` (a default, or classified above public) or `key?: T | null`, the rules as an `ObjectRule` constant, and `validate<Name>(value: unknown): Validation<Name>`, which checks a JSON value against every rule the PHP codec checks, in the order it reads the keys, and gives the first value that breaks one with its `FieldPath` text. A root is named after its codec without `Codec` (`ReceiptV1`), a bound object after its class and the version (`ConsistencyTokenV1`); two declarations of one name are `generate_name_collision`. The id and value objects' pattern and lengths come from `CodecValue::$form` (`Codec\Domain\Dto\StringForm`), which `JsonSchemaContract` fills from the schema and `RecordContracts` gives `cms_id` (`RecordContracts::ID_PATTERN`); the PHP codec leaves them to the class. The validator does not know a field's classification (a withheld key may be missing), the invariants a class checks across its fields, or an integer past `Number.MAX_SAFE_INTEGER`, which it refuses. `Codec\Domain\TypeScript\LiteralPrinter` prints the constants as Prettier does, so the output passes Prettier, tsc and ESLint unchanged. The golden TypeScript of the comprehensive example is `packages/generators/tests/Descriptor/Fixtures/Comprehensive/typescript/generated` (`packages/generators/tests/TypeScript/TypeScriptContractsTest.php`), which `tsconfig.json` includes. The Codecs suite's `tests/Codecs/TypeScriptValidatorsTest.php` runs the workbench's validators in Node, through `tests/Support/TypeScript/run-validators.ts` (Node's type stripping, and the modules compiled to CommonJS with the pinned TypeScript), against what the PHP codecs write for every classification access, against hand-written documents both sides accept or refuse at the same path, and against PHP output with a value planted wrong; Node stands in for the browser until the panel (B1). The page is `docs/addons/codecs.md`.

## The commands' schemas and codecs

The kernel's commands (GUARDRAILS 2.1, 2.2, PRD 6.4, 8.8) have JSON Schemas too, one per command and version in `packages/core/resources/schemas/commands` (`<command>.v<version>.json`: entry.create, entry.revise, variant.release, entry.publish, entry.unpublish, placement.create, placement.set_window and actor.deactivate, each version 1), bound by `ProtocolSchemas::commands()` (`SchemaBinding::$directory` and `$command`, the command's class, whose `#[Command]` must give the binding's version); `ProtocolSchemas::all()` is the contracts' and the commands' bindings, which `composer generate:protocol` and `KernelContracts` read. The codec of a command carries `COMMAND`, the schema as `SCHEMA` (a nowdoc, pretty-printed) and `commandCodec()`, and the generated `KernelCommandCodecs::all()` lists every `CommandCodec`, which `CoreServiceProvider` registers under `CommandCodecs::TAG`; cms:generate writes their TypeScript as `protocol/<Command class>V1.ts`. Two codec kinds serve them: `CodecKind::IntegerValue`, a value object of one int (`ValueBinding::value()` on an integer, `JsonValues::integerValue()` with the schema's minimum and maximum), and `CodecKind::Fields`, the generic fields of a revision of any type (GUARDRAILS 2.4), `ValueBinding::fields(FieldValues::class)` on a `$ref` to `#/$defs/fields`, whose `$defs` must be `Protocol\Domain\FieldValuesSchema::DEFINITIONS` exactly, read by `JsonValues::fieldValues()` as `fieldValue()` reads each value and written by `encodeFieldValues()` in the input form, and checked by the runtime's `fields` rule in TypeScript. `Pipeline\Boundary\CodecCommandContentHasher`, bound to `CommandContentHasher`, hashes a command's name, version and the canonical JSON its codec writes at the highest classification access; a command no codec reads cannot be hashed (`UnknownCommand`). `packages/core/tests/Codecs/ExposedCommandCodecsTest.php` fails when a write action the compiled registry exposes on a surface has no codec, and `tests/Codecs/CommandCodecsTest.php` round-trips every command and holds the PHP codec, the TypeScript validator and opis/json-schema to the same verdict on each rule of each schema. The page is `docs/addons/command-json.md`.

## The queries' schemas and codecs

The kernel's queries (GUARDRAILS 2.1, 2.2, PRD 6.2, 8.8) have two JSON Schemas per query and version in `packages/core/resources/schemas/queries`: `<query>.v<version>.json` for the query's document and `<query>.result.v<version>.json` for its result, bound by `ProtocolSchemas::queries()` (a `SchemaBinding` with `$query` and `$resultCodec` for the document, whose class's `#[Query]` must give the binding's version, and one with `$resultOf` for the result, whose document's class implements `Result`); the kernel's queries are `path.resolve` version 1 (`ResolvePathCodecV1` and `ResolvedPathCodecV1`, the result's explanation the objects of `path-explanation.v1.json` below `#/$defs/path_explanation`) and [the access queries](commands.md#the-access-queries). A property of a schema with `"x-cms-classification"` (`JsonSchemaContract::CLASSIFICATION`, a class above public) is withheld from a reader whose access does not allow it (PRD 12.2): it is not in `required`, has no default and is never null, the codec reads it with `JsonValues::requiredClassified()`, the bound class's constructor argument is its type or `Omitted`, and a class that holds one, in an object or in a list (`CodecObject::classified()`), has `visibleTo(ClassificationAccess)`, which the codec's `encode()` calls. The codec of a query carries `QUERY`, its schema as `SCHEMA` and `queryCodec()`, the `QueryCodec` with the result's codec and its `SCHEMA`, and the generated `KernelQueryCodecs::all()` lists every one, which `CoreServiceProvider` registers under `QueryCodecs::TAG`; `ProtocolSchemas::result()` refuses a query whose result has no codec. cms:generate writes their TypeScript as `protocol/<Query class>V1.ts` and `protocol/<Result class>V1.ts`. `packages/core/tests/Codecs/ExposedQueryCodecsTest.php` fails when a query action the compiled registry exposes on a surface has no codec, and `tests/Codecs/QueryCodecsTest.php` round-trips every kernel query and result and validates what the codecs write against the schemas with opis/json-schema. The surface contract tests build a `QueryContractCase` per query action and surface its `#[Action]` lists (`tests/Support/SurfaceContract`: `QueryScenario` a document the codec refuses, an unauthorized principal and an answered read; `QueryContractKernel` the real `QueryPipeline` over the `QueryWorld`'s fakes; `RestQueryProfile` with a Bearer service credential, `McpQueryProfile` with an agent's and, `InertiaQueryProfile` with a Bearer service credential), and a query on a surface without a query profile, the CLI until it serves reads, or without a `QueryCodec` fails its case. The page is `docs/addons/query-json.md`.
