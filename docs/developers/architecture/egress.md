# Egress

The one-line rule is in `CLAUDE.md`: outbound HTTP only in `Cbox\Cms\Core\Egress`. This page lists what counts and how the gateway works.

## What counts as egress

Outbound HTTP (Guzzle, the Http facade, HTTP clients, `curl_*`, sockets, `file_get_contents`) is allowed only in the gateway namespace `Cbox\Cms\Core\Egress`, which goes through the SSRF guard. That includes everything PHP's URL wrappers let fetch a URL or that runs a program: `fopen`, `file`, `readfile`, `copy`, `get_headers`, the `*_file` functions, `SplFileObject`, `SplFileInfo::openFile()`, `DOMDocument`, `XMLReader`, `pfsockopen`, `stream_context_create`, `socket_*`, `ftp_*`, `proc_open`, `exec` and the other program functions, backticks, Symfony Process and Illuminate Process. Writing, moving, removing or listing through ftp:// counts too (`file_put_contents`, `rename`, `unlink`, `mkdir`, `rmdir`, `opendir`, `scandir`, `dir`, `DirectoryIterator`, `FilesystemIterator`, `RecursiveDirectoryIterator`), as do `touch`, `chmod`, `chown` and `chgrp`, which a registered wrapper serves, and `bzopen`, as do the filesystems that pass a URL on (`Illuminate\Filesystem`, the `File` facade, Symfony's Filesystem), XML that fetches entities or documents (`simplexml_load_string`, `XSLTProcessor`, `SoapServer`) and mail (`mail`, `mb_send_mail`, `error_log`). So do the framework's and the packages' own HTTP senders, which `allow_url_fopen` does not stop, with their contracts, because a type-hinted contract gets a client without naming it: storage disks (the `Storage` facade, `Illuminate\Contracts\Filesystem`, `League\Flysystem`, `Aws`), mail (the `Mail` facade, `Illuminate\Mail`, `Illuminate\Contracts\Mail`, `Symfony\Component\Mailer`), notifications (the `Notification` facade, `Illuminate\Notifications`, `Illuminate\Contracts\Notifications`), the image manager (the `Image` facade, `Illuminate\Image`), `Symfony\Contracts\HttpClient` and HTTPlug (`Http\Client`, `Http\Discovery`), and the container ids that resolve them, `Egress::SERVICE_IDS`: 'files', 'filesystem', 'filesystem.disk', 'filesystem.cloud', 'mailer', 'mail.manager', 'image' and 'http'. A quoted string that spells one of these names counts as well, so a string callable such as `array_map('file_get_contents', ...)`, `[$info, 'openFile']`, `app('GuzzleHttp\Client')` or `app('filesystem')` is reported; an array key or offset is not, and `Egress::ALLOWED_WORDS` lists the strings that are only words, such as 'file' in a report. The lists, each entry with its reason, are the testkit's `Cbox\Cms\Testkit\Phpstan\EgressNames` (`#[Internal]`, which `Egress::ALLOWED_WORDS` lets spell them, and which the testkit's `HookIoRule` reads too), and the allowed local uses, each with its reason, are in `tests/Support/Arch/Egress.php`; the Arch suite reads exact names from the tokens (`ReferenceScan`) and fails an allowance no code uses. Read and write local files through code that refuses a path naming a stream wrapper before it touches it, with `Cbox\Cms\Contracts\Storage\LocalPath::namesStreamWrapper()` (`#[Internal]`), as the generators' `Schema\Boundary\LocalFile` and the writers `FileRegistryCache`, `FilesystemGeneratedOutput` and `FilesystemSchemaFiles` do. The stat functions (`is_file`, `file_exists` and the like) are not on the lists. The runtime contract also turns `allow_url_fopen` off (`php.allow_url_fopen` in `cms:doctor`).

## The egress and mail gateways

The egress gateway (GUARDRAILS 2.3, 3, 5, PRD 7.14) is the contract `Cbox\Cms\Contracts\Egress\EgressGateway` (`#[Experimental]`): `get(EgressRequest): EgressResponse`, a GET of a `Contracts\Egress\EgressRequest` (a `HostClass`, a lowercase word the caller names the kind of destination with, the URL and `EgressHeader`s). The mail gateway is the contract `Contracts\Egress\MailGateway` (`#[Experimental]`): `send(OutboundMail)`, one plain-text mail to one recipient, failing with `EgressFailed` and `egress_mail_failed`. Both, with `EgressResponse`, `EgressFailed` and `EgressOutcome`, live in the contracts module, and the counter names are constants of the interfaces (`EgressGateway::REQUESTS`, `FAILURES`, `HOST_CLASS`, `OUTCOME`, `MailGateway::MAILS`). `cbox-cms.contracts` binds them through `ContractBindings`, as singletons, to `Core\Egress\Adapter\SsrfEgressGateway` and `LaravelMailGateway` (both `#[Experimental]`) unless an application names another class; `packages/core/tests/Egress/EgressContractBindingsTest.php` holds the swap. `SsrfEgressGateway` is on Laravel's HTTP client and `cboxdk/laravel-ssrf` (`~1.5.0`, used directly; `CoreServiceProvider` registers its `SsrfServiceProvider`): each request is built as the package's `Http::ssrf()` builds it, redirects off and the package's `GuardRequestMiddleware` with https as the only scheme, which checks the URL when it is sent, refuses private, reserved and metadata addresses, blocked hosts and credentials in the URL, and pins the connection to the checked addresses (CURLOPT_RESOLVE); the timeouts are `cbox-cms.egress.connect_timeout_ms` (2000) and `timeout_ms` (10000), read by `Egress\Boundary\EgressConfig` into `Domain\Dto\EgressSettings` when the gateway is built. It returns the response for every status but a 3xx and otherwise throws `EgressFailed` with `egress_blocked`, `egress_redirect_refused`, `egress_unavailable` (retryable) or `egress_guard_disabled` (the package's `ssrf.enforce` or `ssrf.pin_dns` is off, so it sends nothing), whose message never holds the URL. It counts `cms.egress.requests`, and `cms.egress.failures` for every outcome but a 2xx, under `cms.egress.host_class` and `cms.egress.outcome` only. `LaravelMailGateway` hands the mail to Laravel's default mailer from `mail.from`. The Arch suite holds the gateways to exactly the names `Egress::ALLOWED` gives `SsrfEgressGateway` (`Illuminate\Http\Client\`) and `LaravelMailGateway`; the namespace `Core\Egress` is not exempt as a whole. The testkit has the fakes `Cbox\Cms\Testkit\Egress\FakeEgressGateway` and `FakeMailGateway` and the shared suites `EgressGatewayContract` and `MailGatewayContract` with their harnesses, run against the fakes in `packages/testkit/tests/Contract` and against the adapters in `packages/core/tests/Contract` (`SsrfEgressGatewayHarness` over `Tests\Egress\SsrfEgressGatewayWorld`, laravel-ssrf's `FakeResolver` and Laravel's `Factory::fake()`; `LaravelMailGatewayHarness` over a `SwitchableTransport`). `docs/security/egress.md`, `docs/addons/contracts/egress-gateway.md` and `mail-gateway.md` document them.
