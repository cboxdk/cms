# The documentation gate

Gate 10 holds `docs/` to the inventory of the code, and `RepositoryDocsTest` runs the same audit in gate 5.

## composer docs:check

Gate 10 of GUARDRAILS 10 (GUARDRAILS 2.4, PRD 14.4) is `composer docs:check`, `tools/bin/docs-check.php [--root=<dir>]` of the tooling's feature `Cbox\Cms\Tooling\Docs`. It exits 1 on any finding and prints each as `<file>:<line>: <message>` or `<subject>: <message>`, such as `<extension point>: undocumented`. The inventory is read from tokens, with no autoloading: every interface, attribute class and trait in `packages/*/src` that is not `#[Internal]`, every class there with `#[Command]` or `#[Hook]`, and every `*.json` in `packages/*/resources/schemas`, less `Docs\Domain\Exclusions`, where each entry has a reason and a stale one is a finding. The documentation is one tree, `docs/` at the repository root; a Markdown file below `packages/` is a finding. A page is a Markdown file below `docs/` and declares what it documents with `<!-- extension-point: <FQCN or repo-relative schema path> -->`; there is no central list, and each extension point is on exactly one page. A page that declares one has at least one `<!-- example: <path> -->` on the line above a fenced block that is the file byte for byte: a `*Test.php` that a gate-5 suite of `phpunit.xml` includes and that calls `expect()` or an assert method or uses a trait of the inventory. `<!-- example-file: <path> -->` embeds a support file or fixture the same way, and its name without the extension appears in an example test on the same page. Every fenced block on every page is such an embed, so a command goes in inline code, and every path in a marker is repo-relative. The layout is the cboxdk docs standard (`Docs\Domain\DocsLayout`): the root of `docs/` holds only and always `index.md`, `quickstart.md` and `requirements.md`; every folder below it, nested ones too, has an `_index.md`; every page starts with frontmatter with `title`, a whole-number `weight` and `description`, and an `_index.md` has the lowest weight in its folder. The root of the repository has `README.md`, `LICENSE`, `SECURITY.md` and `CONTRIBUTING.md` (`DocsLayout::REPOSITORY_FILES`). No relative link or image in `docs/`, `README.md`, `CONTRIBUTING.md` or `SECURITY.md` dangles (`Docs\Domain\DocsLinks`): the path stays in the repository and exists, and a `#fragment` on a link to a Markdown file names a heading there by GitHub's anchor. Below `docs/` there are only pages and the screenshots of `Docs\Domain\Screenshots` in `docs/screenshots/<key>.svg` (`Docs\Domain\ScreenshotAudit`): every entry has its file, every file an entry, a page outside `docs/screenshots` (or one of those three root files) embeds every entry, `README.md` embeds at least one, and each embed's alt text is the entry's caption. `composer docs:screenshots [-- --only=<key>]` captures them: it runs each entry's command from the root with colour on and draws the output as a terminal in SVG (`Docs\Domain\TerminalSvg`), and fails, writing nothing for the shot, on an exit code other than the entry's. A command whose output depends on the clock, the machine or the services runs in a scene (`Docs\Domain\Scene`): `php tools/bin/docs-scene.php <scene> <artisan command>` boots the workbench from `testbench.yaml`, binds a `FakeClock` and the core's fake doctor probes (`Docs\Adapter\SceneFixtures`) and runs the command, and the entry's `prompt` is what the image's prompt line shows; so a capture gives the same bytes on any machine and day, needs no services, and `tests/Feature/Tooling/Docs/ScreenshotsTest.php` fails when a committed image is not what its command draws now. Run it in the php container after `composer dev:prepare`. `requirements.md` restates `composer.json`'s `require` and `suggest` and `developers/configuration.md` every configuration key; `tests/Feature/Tooling/Docs/ReferencePagesTest.php` holds both. Examples live in `examples/<Suite>/<Topic>/`: `examples/Unit`, `examples/Codecs`, `examples/Contract` and `examples/Postgres` are in those suites, autoload-dev maps `Examples\` to `examples/`, and PHPStan, Rector and Pint cover the tree. An example is a Pest file in the global namespace or a class below `Examples\`, never in `Cbox\Cms`, so `cboxCms.internalUse` reports any `#[Internal]` API it uses, and a page embeds every `*Test.php` there. `composer docs:requirements [-- --root=<dir>]` (`tools/bin/docs-requirements.php`, `Docs\Domain\RequirementsPage` with `Docs\Boundary\RequirementsSources`) writes `docs/requirements.md` from `composer.json`, `package.json` and `compose.yaml`: PHP, Laravel, the extensions and every package of `require`, every package of `suggest` with its reason, Node and the images for development, and the minimums of `cms:doctor`, only when the bytes differ; `tests/Feature/Tooling/Docs/RequirementsPageTest.php` fails when the committed page differs from what it writes, so run it after changing one of those files. `composer docs:errors [-- --root=<dir>]` (`tools/bin/docs-errors.php`, `Docs\Domain\ErrorReferencePage`) writes `docs/reference/errors.md` from the error catalog `Cbox\Cms\Contracts\Errors\ErrorCode`, only when the bytes differ, and gate 10 reports the page as a finding when it is missing or differs from what this checkout's catalog gives, also for a tree named with `--root`; run it after changing the catalog.

## The sections of the documentation

The documentation's sections are topic folders below `docs/`, created only when they have real content: `getting-started/` (the development environment and testing with the testkit), `users/` (people who edit content, with the panel), `developers/` (the architecture, gates and CI, `cms:doctor`, partitions, services, configuration), `sdk/` (the client SDKs and the delivery API), `addons/` (the extension points, each with a running example), `ui/` (the component kit and the panel's slots), `recipes/` (the steps of the common tasks for agents, GUARDRAILS 7.3: add a content type, write a hook in an addon, add a kernel action; each lists its inputs, the files derived from them, the steps and the checks, as a generator would, and embeds the files and tests of a real run) and `security/` (the operating contract, egress and honest scope). A task that follows a recipe keeps it true: when the steps change, the recipe changes in the same commit. `users/`, `sdk/` and `ui/` come with the blocks that build them. Pages are in English, plain and short, with no em or en dashes, no marketing words and no competitor names (integrations, RFCs and dependencies may be named), and claim nothing the code does not do. `README.md` starts with `# Cbox CMS` and describes it as a CMS for Laravel, never as a Laravel CMS.
