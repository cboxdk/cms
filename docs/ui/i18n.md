# Texts and languages

No text of the panel is written in its code (GUARDRAILS 8). Every text a person reads comes from a catalogue by its key, in Danish or English.

## The panel's catalogues

The panel's texts are in `js/panel/src/i18n/catalogues/da.json` and `en.json`, with the same keys. The keys are typed from the English catalogue, so a key the code names that the catalogue lacks, or a key missing in Danish, fails `npm run typecheck`, and `npm run lint:translations` fails on a catalogue with other keys than the others or an empty text. A text names its parameters as `{name}`, which the code fills in. The panel's locale is the application's locale, which the root view writes on `<html lang>`: `da` or `en`, and English for any other.

## The kit's texts

The kit has a few texts of its own, such as the mark of a required field. They live in its catalogues, `js/ui-kit/src/i18n/catalogues/da.json` and `en.json`, with the same keys under `kit.`. A page renders the kit inside `KitI18nProvider` with its locale, `da` or `en`; without one, the kit speaks English. The provider also gives React Aria the same locale, so dates and numbers follow it. Every other text comes from the caller's own translations, and the lint rule against literal text holds the kit to that as it holds the panel.

## No literal text

The lint rule `cms/no-literal-ui-text` of gate 4 fails on literal text a person would read in JSX, such as a text child or an `aria-label`, in the kit, in the panel and, through the SDK's `@cboxdk/cms-panel/eslint`, in an addon's panel code. A text comes from a catalogue.

## Dates, numbers and lists

A date, a number or a list is formatted in the reader's locale through `Intl`, never by hand: the kit's `Timestamp` and `NumberInput` do it, and a contribution calls `formatDate()`, `formatNumber()` and `formatList()` of `usePanelHost()`, which use the panel's locale.

## An addon's texts

A contribution reads its texts with `t()` of `usePanelHost()`, by keys in its own namespace, `<namespace>.<key>`, such as `fixtureaddon.slug_input.preview`, and its labels in the manifest, such as an action's, are keys too. A key outside the addon's namespace shows as the key itself. The panel does not load an addon's catalogue: an addon's manifest has no member that names one, so an addon's text shows as its key in the panel today, and the SDK's test host takes the texts a test gives it. The workbench's browser tests read the fixture addon's texts by their keys for that reason.
